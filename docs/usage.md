## 启动与首次使用

第一次使用可以先跑通一次岗位评估。你需要一份基础简历、一段完整的 JD，以及自己的模型 Key。

### 环境要求

- [uv](https://docs.astral.sh/uv/)：负责准备 Python 3.11 和后端依赖。启动脚本优先使用本机已有的 uv，找不到时会自动安装到项目的 `tools/`。
- [Chrome](https://www.google.com/chrome/)：用于从招聘平台采集岗位。手动录入岗位时可跳过安装。
- **操作系统：** 支持 macOS、Linux 和 Windows 10/11。

首次启动后，约 1.1 GB 的本地检索模型会在后台下载。页面可以先打开，首次检索可能需要等待。

### 启动

下载并解压本仓库，或克隆到本机。启动脚本会安装后端依赖，并使用仓库自带的前端页面。只有重新构建前端时才需要 Node.js 和 npm。

**macOS：** 在访达里双击 `start.command`，也可以在终端进入仓库根目录运行 `./scripts/start/start.sh`。

**Windows：** 双击 `start.bat`，也可以在 PowerShell 里进入仓库根目录运行 `.\start.bat`。

**Linux：** 在终端进入仓库根目录，运行：

```bash
./scripts/start/start.sh
```

看到终端显示启动地址后，在浏览器打开 [http://127.0.0.1:8000](http://127.0.0.1:8000)。使用自定义端口时，以终端显示的地址为准。在启动终端按 Ctrl+C 可停止服务。

> 注：
>
> **macOS：** 若系统拦截 `start.command`，请打开「系统设置 → 隐私与安全性」，在被阻止的提示旁点「仍要打开」。
>
> **Windows：** 第一次运行时如果 Windows 防火墙弹窗，可以直接取消：迁跃只在本机 `127.0.0.1` 上服务，不需要对外开放。

### 首次配置

1. 在右上角「设置」中填写 OpenAI 兼容模型服务的地址、模型名和 API Key，保存后立即生效。使用截图录入时，模型需支持图片输入。
2. 在「材料」中粘贴并保存基础简历，这是岗位评估的必要输入。求职方向、期望城市与月薪、出差条件可写入补充资料。
3. 在「岗位」中点击「添加岗位」，粘贴 JD、链接或招聘页截图；也可通过「采集」读取招聘平台岗位。仅填写链接时，岗位会标记为「JD 不完整」，开始评估前需补充职位描述。
4. 选中岗位，在「评估」页点击「开始评估」。完成后可继续定制简历、研究公司和准备面试。

评估完成后，在该岗位的「评估」页查看总分、八个维度的依据和投递建议。

详细配置见[设置与配置](#设置与配置)。启动或运行中遇到问题，可按现象查阅[常见问题与排查](#常见问题与排查)。

### 引导与示例数据

第一次打开迁跃时会弹出「第一次使用迁跃？先看教程」（之后点顶栏的问号再打开，标题是「使用引导」），可以选：

- **本页引导**：只介绍当前这一页。
- **全部引导**：从导航栏的「总览」开始，一页介绍完自动到下一页（采集、岗位、材料、成果、检索、助手），最后是设置页（AI 模型 API、联网搜索、接入 Agent、隐私）。
- **查看示例数据**：不走引导，只切到示例数据自己翻看；已经在示例里时这里换成「退出示例数据」。点右上角 × 直接关掉。

引导都在**示例数据**上进行：一份虚构的求职记录（陈XX 的二十多个岗位、评估、定制简历、面试准备和助手对话）。还在你自己的数据里时，迁跃会先切到示例数据（页面会重新载入一次），引导结束后切回来；示例数据打包在前端里，只能浏览，不读写后端，不会影响你自己的数据。

每一步高亮页面里的一个控件并说明用法，第一步先指出导航栏里的这一页。点「下一步」或压暗处往后，点右上角「退出」或按 Esc 结束。此外，在自己的数据里每一页第一次打开时会自动播放这一页的引导，同样用示例数据；看过（或在全部引导里走过）的页面不再自动播放。自己主动切到示例数据翻看时不会自动弹引导，想看引导点顶栏的问号或「设置 → 看引导」即可。

也可以在「设置 → 示例数据与引导」里进入或退出示例数据；进入后顶栏显示「正在看示例 · 退出」。

## 设置与配置

模型和搜索服务可在工作台右上角的「设置」里修改，保存后立即生效。设置页保存的值优先于环境变量和 `backend/.env`。可先点击「测试模型」或「测试搜索」验证当前填写的配置，确认可用后保存。模型测试会发送固定问候，可能产生少量费用。搜索测试使用固定公开词条。文件中的配置项见[配置模板](../backend/.env.example)。

| 配置项 | 在哪里填写 | 何时需要 |
| --- | --- | --- |
| 模型地址、模型名、API Key | 设置 → 模型服务，或 `QIANYUE_LLM_BASE_URL`、`QIANYUE_LLM_MODEL`、`QIANYUE_LLM_API_KEY` | 评估、简历定制和助手共用这一组。要发招聘页或聊天截图，选择支持图片输入的模型 |
| 联网搜索 | 设置 → 联网搜索，或 `QIANYUE_SEARCH_PROVIDER`、`QIANYUE_SEARCH_API_KEY` | 公司研究、面试准备查公开资料时使用。默认 `ddgs` 免 Key，也可选博查、智谱、Tavily、Brave、Serper 或 Exa |
| 评估预算 | `backend/.env` 中的 `QIANYUE_LLM_INPUT_TOKEN_BUDGET` | 默认 30000 个估算 token。可配合下面的并发数限制单次任务和批量任务的用量 |
| 本机检索模型 | `QIANYUE_EMBEDDING_MODEL`、`QIANYUE_RERANK_MODEL` | 分别用于按语义召回材料和重新排序。首次使用按默认值下载即可 |

启动脚本默认优先使用国内镜像。如需使用官方源，启动前设置 `QIANYUE_OFFICIAL_SOURCE=1`。

### 本地检索模型

检索功能使用的语义召回模型和重新排序模型在本机运行，不调用模型服务，也不需要 Key。后端启动后由 fastembed 在后台下载到 `data/models/`，两个模型合计约 1.1 GB。下载时可以照常使用页面；还没下完就开始检索的话，会等下载完成再继续。若后台下载失败，首次检索时会重试。

| 用途 | 模型 | 下载位置 |
| --- | --- | --- |
| 语义召回（Embedding） | `jinaai/jina-embeddings-v2-base-zh` | [jinaai/jina-embeddings-v2-base-zh](https://huggingface.co/jinaai/jina-embeddings-v2-base-zh) |
| 重新排序（Rerank） | `BAAI/bge-reranker-v2-m3-int8`，fastembed 实际下载同一模型的 ONNX 版本 `onnx-community/bge-reranker-v2-m3-ONNX` | [onnx-community/bge-reranker-v2-m3-ONNX](https://huggingface.co/onnx-community/bge-reranker-v2-m3-ONNX) |

模型名称见[后端配置](../backend/app/core/config.py)。可通过 `QIANYUE_EMBEDDING_MODEL` 和 `QIANYUE_RERANK_MODEL` 更换模型。更换 Embedding 模型时，先停止服务并移走 `data/vectors/`，重新启动后，程序会用新模型重建索引。启动脚本默认探测 `hf-mirror.com`，根据探测结果选择模型下载端点。若已设置 `HF_ENDPOINT`，则使用指定地址。

### 启动参数

| 需求 | 配置方式 |
| --- | --- |
| 修改端口 | macOS / Linux 运行 `QIANYUE_PORT=8100 ./scripts/start/start.sh`。Windows PowerShell 先运行 `$env:QIANYUE_PORT="8100"`，再运行 `.\start.bat` |
| 修改数据目录 | `QIANYUE_DATA_DIR=其他目录 ./scripts/start/start.sh`（相对路径以仓库根目录为基准） |
| 指定 Chrome 路径 | 在 `backend/.env` 中设置 `QIANYUE_CHROME_PATH` |
| 设置批量评估并发数 | `QIANYUE_MAX_CONCURRENT_JOBS`，默认 3 |
| 通过配置文件设置模型 | 写入 `backend/.env`；与设置页同时配置时，以设置页为准 |
| 查看全部接口 | 启动后访问 [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs) |

## 材料

**操作**：在材料页编写基础简历，选填 STAR 经历和补充资料；也可点击「和助手一起写」。

**系统行为**：每次保存均生成一个新版本并保留旧版本；评估、定制和面试准备读取当前版本。

**输出**：作为全部 AI 产出的真实信息依据。所有产出只能使用材料中记录的真实经历。

| 材料类型 | 填写要求 | 内容说明 |
| --- | --- | --- |
| 基础简历 | 必填 | 简历全文。定制简历不会修改基础简历，而是另存一份 |
| STAR 经历 | 选填 | 每段经历使用一个二级标题，写明情境、任务、行动和结果。用于补充简历未能容纳的细节，定制和面试准备会从中查找证据 |
| 补充资料 | 选填 | 求职方向、期望城市和月薪、能否出差或驻场、到岗时间、作品和证书 |

- **历史版本**：入口位于材料标题旁。选择版本可查看内容，也可将其恢复为最新版本；恢复会另存一版，不删除其他版本。内容未变化时不新增版本。
- **和助手一起写**：助手先读取当前版本，每次询问一个问题。编写完成后展示整份内容，经用户确认才保存为新版本。只能使用用户明确提供或原有材料中已有的内容；出现未提供的数字或技术词时，程序会拒绝保存。
- **在对话中整理 STAR**：向助手发送「帮我把这段经历整理成 STAR 存起来」，并附上经历内容。信息不完整时，助手每次询问一个缺失部分。整理完成后先展示内容，确认后追加到 STAR 经历；同名经历会被替换，旧版本仍保留。与原始表述不同的措辞会作为提醒一并展示。
- 任一材料发生变化（包括新增一段 STAR）后，对同一岗位再次评估时会重新计算，不复用旧报告。

## 岗位

**操作**：点击「添加岗位」，粘贴 JD 文本或链接，也可将招聘页截图放入 JD 输入框，并在截图下方继续输入文字。

**系统行为**：包含截图时，添加过程中将截图一次性提交给模型识别；识别出的公司、职位和 JD 与手动填写内容一并保存，手动填写的字段优先。同一链接或同一 JD 仅保存一条岗位记录。

**输出**：形成岗位列表。选中岗位可查看详情，并在七个功能页执行相应任务。

### 岗位生命周期

岗位同时具有两条相互独立的状态线：**应聘阶段**记录实际求职进展，仅由用户修改；**处理进度**表示迁跃中的材料和评估状态，由系统根据当前数据计算，不作为应聘阶段使用。

应聘阶段存储在 `stage` 字段中：

| `stage` | 界面含义 | 列表类别 |
| --- | --- | --- |
| `not_applied` | 未投递；新添加岗位的初始阶段 | 未开始 |
| `applied` | 已投递 | 进行中 |
| `assessment` | 已笔试，包含测评 | 进行中 |
| `interviewed` | 已面试，不区分轮次；等待结果时仍属于此阶段 | 进行中 |
| `offer` | 已获 Offer | 已结束 |
| `rejected` | 未通过 | 已结束 |
| `withdrawn` | 已放弃，包括不再考虑或拒绝 Offer | 已结束 |

处理进度通过接口字段 `prep` 返回，不单独写入数据库：

| `prep` | 界面含义 | 计算条件 |
| --- | --- | --- |
| `incomplete` | JD 不完整 | 尚未提供 JD |
| `unevaluated` | 待评估 | 已有 JD，但没有未删除的评估报告 |
| `evaluated` | 已评估 | 已有评估报告，列表显示最近一次评分 |

阶段与进度遵循以下规则：

- **修改阶段**：点击详情中的阶段标签。可跳转至任意阶段，也可改回之前的阶段，不设置顺序限制。每次修改均关联一个 `happened_on` 日期（投递日期、面试日期等），默认当天，可选择过去的任意日期，但不能晚于当天。
- **仅记录已发生的事项**：已预约但尚未进行的笔试或面试不改变阶段；长时间没有新消息也不会自动修改阶段。
- **阶段历史**位于「岗位信息」页。每条记录对应一次操作，左侧为操作时间，右侧记录类似「从『已投递』改为『已面试』，面试日期：10-20」的内容。总览中的投递和面试节奏按 `happened_on` 计算。
- **处理进度随数据更新**：补充 JD、完成评估或删除评估报告会改变 `prep`；删除最后一份评估报告后，有完整 JD 的岗位回到「待评估」。这些操作不会修改 `stage`。

### 岗位列表与详情

- **列表筛选**按应聘阶段类别进行：未开始、进行中、已结束。筛选控件右侧的图标用于切换时间排序或评分排序。
- **看板**：筛选行最右边切换「列表 / 看板」。看板按应聘阶段分 6 列（未投递、已投递、已笔试、已面试、已获 Offer、已结束；已结束包括未通过和已放弃），卡片上写着走到这一步的日期。把卡片拖到另一列，或点卡片上的「…」选「移到…」，会打开改阶段的弹窗，目标阶段已选好，填好日期确认后才修改。点卡片回到列表并打开这个岗位。搜索和排序在看板里同样生效。
- **疑似重复**：更换名称后重新发布，或在多个平台分别发布的岗位，会标记「疑似重复 #编号」。系统仅提示，不自动合并。
- **编辑基本信息**：可修改公司、职位、城市、薪资、链接（清空即移除）和来源。若修改后的链接已被其他岗位使用，系统会提示对应岗位。
- **删除**采用软删除：岗位不再显示在列表中，采集也不会再次将其写入。

七个功能页分别为：岗位信息（JD、基本信息、阶段历史）、评估、定制简历、公司研究、沟通建议、面试准备、模拟面试。以下各节分别说明。

## 采集

**操作**：在采集页选择平台，填写各平台的数量、关键词和城市，选填筛选条件，然后点击「开始采集」。

**系统行为**：后台使用专用 Chrome 打开各平台搜索页，将读取到的岗位保存至岗位列表。每种「平台 × 关键词 × 城市」组合视为一个搜索，并按顺序逐个执行。遇到登录或验证时暂停该平台的采集，在专用浏览器中打开对应页面并置于前台。

**输出**：新增岗位及右侧的采集记录（时间、搜索内容、新增数量和状态）。打开记录可查看每个搜索的处理结果。

采集本身不需要模型 Key，默认不执行评估。数量指每个搜索新增的岗位数（1–20，默认 10）；单次采集最多包含 25 个搜索，新增总数不超过 100 个。

**支持的平台**：

| 平台 | 登录要求 | 读取方式 | 单次搜索读取范围 |
| --- | --- | --- | --- |
| 前程无忧 | 无需登录，也可登录 | 搜索结果包含完整职位描述，不打开详情页；数量不足时点击「下一页」 | 每页 20 个，最多 5 页 |
| 智联招聘 | 未登录时仅可读取 20 个，登录后可读取更多 | 搜索结果包含完整职位描述，不打开详情页；登录后数量不足时滚动加载下一批 | 每批 20 个，最多 5 批 |
| 猎聘 | 需要登录 | 逐个打开详情页读取职位描述；列表数量不足时点击「下一页」。刚登录时可能要求短信验证，完成一次即可 | 每页约 40 个，最多 5 页 |
| BOSS 直聘 | 需要登录 | 搜索结果包含职位名、公司和薪资，数量不足时滚动加载下一批；逐个打开详情页读取职位描述 | 每批 15 个，最多 5 批 |

仅在需要时翻页：从读取到的岗位中排除已保存记录后，若仍未达到指定数量，才读取下一页。因此，间隔数日后再次执行相同搜索，会继续查找后续的新岗位。已有完整 JD 的岗位不再打开详情页，也不计入本次新增数量。

**筛选条件**（均为选填）：

| 条件 | 筛选规则 | 无法识别时的处理 |
| --- | --- | --- |
| 最低月薪（千元） | 岗位月薪上限低于设定值时跳过。例如，设定值为 20 时，「15-25K」会保留 | 「面议」、按天计薪等非月薪范围不参与筛选 |
| 工作年限 | 岗位要求的最低年限比用户工作年限多一年以上时跳过。例如，用户有 4 年经验时，「5-10年」保留，「10年以上」跳过 | 未写明经验要求时不筛选 |
| 排除词 | 职位名包含排除词时跳过 | — |
| 与关键词无关的岗位 | 配置模型 Key 后，每页将职位名提交给模型，跳过明显无关的岗位（实测搜索「前端开发」时，跳过芯片设计岗位「数字前端工程师」）。仅发送职位名，不发送公司和 JD | 模型出错或判定大部分职位均无关时，本页不筛选；被跳过的职位名记录在采集结果中 |

被跳过的岗位不读取详情、不保存；结果中会记录跳过数量及各项原因。勾选「采集完成后自动评估新增的岗位」后，采集结束即对本次新增岗位发起一次评估。

**未登录时仅保存列表信息**：可使用终端命令的 `--list-only`、向助手说明「只存列表」，或在接口中设置 `"list_only": true`（采集页不提供此选项）。此模式不读取详情页，仅保存列表信息；没有职位描述的岗位标记为「JD 不完整」。2026-11-17 使用全新的专用浏览器环境实测：前程无忧和猎聘可以翻页，分别读取到第 3 页和第 2 页；智联仅提供第一批 20 个；BOSS 仅提供第一批 15 个，且不含薪资。若需在智联和 BOSS 上读取更多岗位，必须先登录。

**访问节奏和数量限制**（实现位于 `backend/app/collectors/pacing.py`）：

| 项目 | 数值 |
| --- | --- |
| 翻页前 | 等待 6–11 秒 |
| 读取单个岗位详情前 | 等待 5–12 秒 |
| 每读取 6 个详情 | 暂停 22–45 秒 |
| 同一平台两次搜索之间 | 至少间隔 22 秒 |
| 每个平台 24 小时内 | 最多新增 200 个 |

逐条读取详情通常比只读列表慢。实际耗时取决于平台响应、登录状态和需要打开的详情页数量。平台仍可能限制访问。

补充说明：

- **专用浏览器**使用本机 Chrome，但采用独立用户目录 `data/browser/`，与日常使用的 Chrome 互不影响。无法找到 Chrome 时，在 `backend/.env` 中设置 `QIANYUE_CHROME_PATH`。
- **采集在后台静默执行。** 标签页在后台打开，不会将浏览器置于前台；浏览器处于最小化、关闭或退出状态时，采集也会在后台自动启动。
- **需要登录或验证时，专用浏览器会自动显示对应页面。** 用户完成登录或验证后，可点击采集记录中的「从断点继续」，也可重新发起相同采集；已保存岗位不会重复读取。登录状态保存在 `data/browser/`。如需提前登录，可使用终端命令 `--login`，或向助手发送「打开猎聘让我登录」。
- **BOSS 和猎聘未登录时无法读取完整职位描述。** 截断内容不会作为完整 JD 保存；无法读取的职位描述以「JD 不完整」保存，补充 JD 后才能评估。
- **采集使用用户本人账号，相关风险由用户承担。** 访问节奏和数量上限仅用于降低风险，平台仍可能要求验证或限制账号。
- **程序在页面上的行为**：仅连接自身新开的标签页，使用完成后断开并关闭；监听页面网络请求、打开地址并读取页面内容；翻页时点击页面中的「下一页」，或将列表滚动到底部。不修改浏览器指纹，不改写页面，不模拟鼠标轨迹，不代替页面向平台发送请求。BOSS 和智联的列表页启用「焦点仿真」，使后台标签页也能滚动加载下一批。实现见 [architecture.md](architecture.md#8-岗位采集)。
- **遇到登录、验证或访问限制时停止。** 不处理验证码，不绕过登录，不重试。单个平台停止不影响其他平台。
- 同一时间只能执行一次采集。

## 评估

**操作**：在岗位的「评估」页点击「开始评估」，可填写本次重点条件（例如「只考虑上海，月薪不低于 30K」）；也可在岗位列表中勾选多个岗位进行批量评估。

**系统行为**：对照基础简历、补充资料和 STAR 经历，由模型对八个维度评分并写明依据；总分、信息覆盖率、置信度和投递结论由程序按固定权重计算。

**输出**：一份评估报告，包含结论、各维度得分及依据、硬性阻断和待核实问题。

- 模型仅给出各维度 1–5 分（或「不可评估」）及依据，程序计算总分。不可评估的维度不计入分母；存在「已确认」的硬性阻断时，结论不能为推荐投递。规则见 `backend/prompts/evaluation.md`。
- **硬性阻断**（例如学历、城市、年限的硬性要求）要标记为「已确认」，必须摘录 JD 或材料中的原句。程序逐字核对，找不到原句时降为「待核实」。
- **边界分数复评**：相同输入评估两次，总分可能出现零点几分的差异。首次总分恰好位于结论分数线（3.5、4.0、4.5），或比分数线低 0.1 分时，系统使用相同输入再评估两次，每个维度取三次结果的中位数，报告开头的「复评」一行记录各次总分。此类岗位会额外消耗约两倍 Token。
- **输入未变时复用**：JD、材料和条件均未变化时，再次评估直接返回已有报告，不调用模型。如需重新执行，点击「重新评估」。
- **批量与断点续跑**：一次评估多个岗位时，并发数为 3（`QIANYUE_MAX_CONCURRENT_JOBS`）。中途停止或服务重启后，可在任务面板点击「从断点继续」，已完成的岗位不会重新评估。
- 缺少简历或岗位没有完整 JD 时，不调用模型，直接说明缺失内容。
- 评估时会将 JD 中识别出的公司名、职位名补充到岗位的空字段，已填写的字段不变。
- 补充资料和 STAR 超出输入容量时，截断超出部分（优先保留补充资料），并在报告中标注。

## 能力画像

**操作**：在岗位页勾选 2–15 个目标岗位，点击「能力画像」；也可向助手发送「#2 和 #3 这两个岗位普遍要什么」。

**系统行为**：归纳这些 JD 普遍要求的能力，由程序统计各项能力对应的岗位数量；再对照用户材料，「有」「部分有」均须摘录材料原句并由程序核对。

**输出**：一份不归属于单个岗位的成果，说明此类岗位的共性要求及用户差距，可在成果页查看。

## 定制简历

**操作**：在岗位的「定制简历」页点击「开始定制」，可填写本次要求。方案生成后逐项勾选，也可点击「改一下」直接修改为所需表述。

**系统行为**：针对 JD 的每条要求，在补充资料和 STAR 经历中查找证据，并连同基础简历提交给模型。模型仅提出按行定位的修改（替换、删除、插入、移动），每条附对应的 JD 原文和所用证据；程序核对后暂停，等待用户确认，仅应用已勾选的修改。

**输出**：一份仅用于当前岗位的定制简历，基础简历保持不变。

- **逐条修改左右对照**：原文删除的文字显示删除线，新增内容中高亮新增文字。勾选状态变化后，下方预览同步更新。
- **程序校验范围**：新内容出现材料中没有的数字或英文技术词时，该条修改退回重写；引用不存在的证据、行号越界或重叠时也会退回。
- **措辞升级**：可以使用更有力的动词，但将「参与」改为「负责」等提升职责层级的表述会单独列为一项并标记「措辞升级」，由用户决定。模型还会逐条对照原文复核措辞，发现的问题标注在对应条目上，不会自动拒绝。接受修改前应逐项核对。
- **默认勾选**无需用户确认且没有措辞提醒的修改。标记「需要你确认」的条目表示模型无法确定，需用户确认属实。
- 用户手动修改的条目按提交内容原样应用，不再经过程序核对。
- 「简历里补不上的缺口」指岗位要求中缺少材料证据的部分；「需要你补充的信息」是模型需要用户回答的问题。将相关信息补充到 STAR 经历后再次定制，可提高简历的针对性。
- 停留在「等你确认」状态时可关闭服务，下次启动后方案仍保留。不再需要该方案时，点击「放弃这次定制」。

## 公司研究

**操作**：在岗位的「公司研究」页开始任务，可填写重点关注的方面（例如「重点看是不是外包驻场」）。岗位必须先填写公司名。

**系统行为**：Agent 自主决定搜索内容和需要打开的网页；程序核对其引用的来源。

**输出**：带来源的研究报告。每项论述后附来源编号，文末列出链接，并标明「已读原文」或「只有搜索摘要」。

- 模型引用工具未返回过的来源时，退回重写。
- 总体判断由程序校验：未打开原文的论述，置信度最高为「中」；「有风险」必须有已读原文的用工或经营类风险作为依据；公司主体未确认时，只能得出「信息不足」。
- 单次研究最多搜索 6 次、读取 4 个网页；输入用量随搜索结果和网页正文长度变化。
- 搜索默认使用免费的 DuckDuckGo（无需 Key），偶尔可能无法获得结果。可在设置页改用博查、智谱、Tavily、Brave、Serper 或 Exa，并填写相应 Key。这六种接入的有效 Key 搜索结果尚待验证，可在设置页使用自己的 Key 测试。
- 在尚未获得任何搜索结果时，若搜索失败两次（断网、Key 不正确、额度耗尽），研究直接停止并说明原因。
- 无法读取网页正文时，报告只能引用搜索摘要。

## 沟通建议

**操作**：在岗位的「沟通建议」页保存招聘方聊天内容（招聘方说的、我说的或整段粘贴），也可将聊天截图放入输入框，然后点击「要建议」。没有聊天记录时，系统生成首次打招呼的消息。

**系统行为**：Agent 按需检索用户材料，读取该岗位的评估和公司研究，分析对话并起草回复；程序核对草稿中的数字和技术词是否具有出处。

**输出**：对话分析及可复制的回复草稿。

- 草稿仅保存在本地，由用户自行修改和发送。系统不发送消息，也不操作招聘平台。
- 草稿中的【】表示需要用户填写的内容（期望薪资、到岗时间、能否接受驻场）。这些事项由用户决定，系统不代为填写。
- 分析中引用的「对方原话」必须能在已保存的聊天记录中逐字找到；草稿中的数字和英文技术词必须在材料、JD 或对话中具有出处，且不得包含手机号。否则退回重写。
- 对话显示进展变化（例如对方预约面试）时，建议中会提示修改阶段，但不会自动修改。
- 保存截图时，由模型识别为区分发言方的聊天记录，图片本身不保存（没有 Key、交给 Agent 识别时，截图在 `data/uploads/` 保留 7 天）。
- 新增聊天内容后再次请求建议，会生成一份新建议；内容未变化时返回已有建议。

## 面试准备

**操作**：在岗位的「面试准备」页开始任务，可填写面试轮次、面试官身份和重点担忧。

**系统行为**：根据 JD、简历和 STAR 经历预测问题，同时使用该岗位已有的评估和公司研究，并联网查找该公司该岗位的面经。

**输出**：10–14 道题，分为技术与专业、项目深挖、行为问题、风险与缺口四类；每道题包含回答要点、可能的追问和待复习知识点，另附反问清单和准备清单。

- **面经**：程序使用「公司 + 岗位核心词 + 面经」固定搜索两次，最多读取三篇。对搜索到的面经中明确列出的面试题，最多采用 4 道；题目下附「面经原文」和出处链接，引用语句必须能在该面经中逐字找到。搜索不到或内容不适用（涉及其他岗位、仅讨论薪资）时，不采用任何面经题，并在报告开头如实说明。面经由网友撰写，准确性不作保证。
- 回答要点仅使用用户材料，不写入面经中他人的经历。标记「JD 原文」「简历原文」的引用均经程序逐字核对；回答要点中的数字和英文技术词必须在用户材料中出现过。
- 「先想清楚」指回答该题必需但材料未记录的事实，例如某个数字的测量方法。面试前应补齐这些信息。

## 模拟面试

**操作**：在岗位的「模拟面试」页开始任务，可填写面试官角色和练习重点，随后一问一答。输入「跳过」可跳过当前问题，按 ⌘/Ctrl + Enter 发送，随时可点击「结束并复盘」。

**系统行为**：AI 面试官每轮仅提出一个问题，回答含糊时追问，面试过程中不点评；结束后逐轮复盘。

**输出**：一份复盘，包含每轮评价、优点、存在问题的原话及修改建议，以及基于用户材料撰写的「更好的回答」。

- 每场最多 8 轮，最后一轮为「你有什么想问我的吗」。
- 复盘引用的用户原话由程序与实际回答逐字核对。「更好的回答」只能使用简历及用户在面试中提供的内容，缺失事实以【】留待补充；其措辞也会再次核对。
- 断线、关闭页面或服务重启后，均可从当前问题继续。
- 仅复盘已经回答的轮次；未回答任何问题便结束时，不生成复盘。
- 也可通过终端进行模拟面试，见[终端命令](#终端命令)。

## AI 使用方式

迁跃的 AI 功能（评估、能力画像、定制简历、公司研究、沟通建议、面试准备、模拟面试）有两种用法，规则、程序校验和保存方式完全相同：

| 用法 | 适合谁 | 怎么用 |
| --- | --- | --- |
| 在设置里填模型 Key | 有 OpenAI 兼容模型服务的 Key | 在各功能页直接发起，或在内置助手里直接说要做什么 |
| 由你的 Agent 代答 | 没有 Key，但在用 Codex、Claude Code、Cursor 等 Agent | 用 MCP 把 Agent 连上迁跃，在 Agent 里说「用迁跃评估岗位 #12」，Agent 替迁跃的模型完成每一步，结果存回迁跃 |

**内置助手是工作台里使用 AI 的主要对话方式，需要模型 Key。** 各功能页也可直接发起对应任务，无需经过助手。没有 Key 时，在功能页点 AI 功能会弹出「交给你的 Agent 来做」，给出一句可以复制到 Agent 里的话。

### 内置助手

使用前，在工作台右上角「设置」中填写 OpenAI 兼容模型服务的地址、模型名和 API Key，保存后立即生效。内置助手与各功能页共用这套配置。

**操作**：用自然语言说明任务，可附加截图（粘贴或拖入输入框）。

**系统行为**：总控 Agent 识别目标岗位，保存用户提供的岗位和聊天内容，将任务交给对应专员（评估、定制、研究、沟通、面试准备、能力画像），并等待完成。

**输出**：专员结论原样显示在对话中，助手仅说明完成状态、成果编号和建议的后续操作。

支持的操作包括：保存岗位、查看岗位和成果、在全部内容中检索（「哪些岗位要 Kafka」）、评估、能力画像、公司研究、定制简历、沟通建议、面试准备、修改应聘阶段、采集岗位、打开专用浏览器供用户登录、共同编写简历和补充资料，以及整理 STAR 经历。

- **需要用户确认的操作**：修改应聘阶段、保存材料、保存 STAR 经历。对话暂停并显示待执行操作，用户确认或取消后继续。一轮包含多个阶段修改时，可仅执行其中一部分。等待确认期间，该对话不能继续。
- **定制简历的逐条确认不在对话中完成**：助手会提示待确认的修改数量，用户需前往岗位的「定制简历」页确认。模拟面试也不在对话中进行。
- **保存用户原文**：用户粘贴的 JD 和聊天内容按消息原文保存，而非模型转述版本。程序无法在用户消息中找到模型给出的待保存文字时，会拒绝保存。
- **截图**：图片直接附加到当前消息并提交给模型，不限张数；图片保留在本机对话历史中。默认开启的文字脱敏不适用于截图：截图会以原图发送，且不再逐次询问，发送前请自行遮挡个人信息；关闭脱敏后，后续轮次仍可读取之前的截图。程序无法将截图中的 JD 与用户原文核对，助手保存时会采用模型根据截图抄录的完整内容；如内容有误，可要求助手修改或前往岗位页修改。包含大量截图的长对话会在后续请求中重复携带图片，Token 用量显著增加。
- **链接**：助手提及岗位或成果时生成可点击链接；使用检索回答时，末尾列出「参考：」。
- **长对话**：对话占用输入预算的六成时，较早内容自动压缩为摘要，保留岗位编号、成果编号、用户要求和决定，最近几轮保持原样。摘要不包含 JD 和报告原文，助手需要细节时通过工具重新读取。用户此前粘贴但未要求保存的 JD，在压缩后如需保存必须重新粘贴。仅当单条消息本身超过输入预算的一半时，该消息会被拒绝。
- 助手等待专员完成后才回答。连接中断不影响专员，任务会在后台继续完成。
- 同一岗位的同类任务仍在执行时，再次发起会返回同一个运行。
- 对话支持改名和删除，入口位于对话列表每条记录右侧的「…」。

### 通过 MCP 接入外部 Agent

MCP 是 AI Agent 连接外部工具的标准协议，也是迁跃提供的**可选**外部接入方式。客户端需支持 Streamable HTTP，具体配置方式见客户端文档。通过 MCP 保存材料还需要客户端支持用户确认框。

后端启动后，在外部 Agent 的 MCP 设置中添加以下连接参数。迁跃设置页底部提供该地址和可复制的配置。

| 配置项 | 值 |
| --- | --- |
| 服务名称 | `qianyue`，也可按客户端要求自定义 |
| 服务地址 | `http://127.0.0.1:8000/mcp` |
| 传输方式 | HTTP（Streamable HTTP） |

外部 Agent 的对话模型由客户端配置。通过 `run_task` 等工具发起的迁跃任务：设置页填了模型 Key 时用迁跃自己的模型；没填时由外部 Agent 代答，见下一节。

连接后可直接发送指令，例如：「看看迁跃里有哪些岗位」「把这个 JD 存进迁跃并评估」「读一下 3 号成果」。

| 类别 | 工具 | 功能说明 |
| --- | --- | --- |
| 读取 | `list_jobs` `get_job` `list_communications` `search_workspace` | 看岗位、按保存顺序读取沟通原文、全局检索 |
| 写入 | `add_job` `update_job` `save_communication` `change_stage` | 新增和编辑岗位、补 JD、保存沟通记录、修改应聘阶段 |
| 材料 | `read_material` `save_material` `save_star` | 读取用户材料；共同修改基础简历和补充资料，整理 STAR 经历。保存前，迁跃要求客户端弹出确认框并展示全文，用户接受后才保存 |
| 任务 | `run_task` `get_task` `list_tasks` `cancel_task` `resume_task` | 发起和查询任务、分页查看任务历史、取消或从断点继续 |
| 代答 | `answer_model_request` `get_model_request` `view_screenshots` | 没有模型 Key 时，交回 Agent 替迁跃模型完成的一步；取一个待代答请求的全文；看用户在迁跃里上传的截图 |
| 定制简历 | `preview_tailoring` `confirm_tailoring` | 按勾选预览并确认修改；用户自己写的新文字可通过 `overrides` 传入 |
| 模拟面试 | `start_mock_interview` `get_mock_interview` `respond_mock_interview` | 开场、查看当前题、提交回答、跳过、提前结束 |
| 成果与总览 | `list_artifacts` `read_artifact` `export_artifacts` `get_overview` | 筛选成果、读正文、获取本机 ZIP 下载链接，查工作台同口径的漏斗、趋势和其他统计 |
| 采集 | `collect_jobs` `open_platform_browser` | 从招聘平台查找岗位；打开专用浏览器供用户登录或验证 |

另提供四类按地址读取的数据（MCP 中称为 Resource）：`qianyue://overview` 进展总览、`qianyue://jobs/{编号}` 岗位、`qianyue://artifacts/{编号}` 成果、`qianyue://documents/{resume|supplement|star}` 用户材料。

使用限制与注意事项：

- **仅限本机使用。** 后端仅监听 `127.0.0.1`，MCP 未设置身份认证，并拒绝来自其他网站的请求。不得将该端口暴露到外网。
- **已连接的 Agent 可读取用户简历和全部岗位**，这些内容会进入该 Agent 所用模型的对话。仅连接受信任的 Agent。
- **通过 MCP 保存 JD 时请核对正文。** 迁跃只能收到外部 Agent 提交的文字，无法与用户原消息核对。
- **修改材料必须由用户确认。** 保存简历、补充资料或 STAR 经历时，迁跃通过 MCP 的确认框（elicitation）直接询问用户，不经过外部 Agent。客户端不支持确认框时不保存，可改用内置助手。材料中原先没有的数字和技术词会在确认框中列出。
- **修改阶段前是否请求确认，由外部 Agent 的客户端决定。**
- **模拟面试**：可以对外部 Agent 说「用迁跃模拟 #3 岗位的技术面，重点练项目经验」。迁跃用设置页的模型出题（没有 Key 时由外部 Agent 代为出题），外部 Agent 逐题展示并转交你的回答。同一场面试可用运行编号续接，也可在岗位的「模拟面试」页继续。提前结束只复盘已回答的题，复盘可通过 `read_artifact` 读取。
- **截图**：在 Agent 里直接发给它的截图，由 Agent 自己识别，再把 JD 或聊天原文作为文本传给迁跃。在迁跃里上传的截图见下一节。
- 长任务默认等待 3 分钟，超时后返回运行编号；任务在迁跃后台继续，可使用 `get_task` 查询。

### 没有模型 Key 时：由你的 Agent 代答

**操作**：把 Agent 用 MCP 连上迁跃后，直接告诉 Agent 要做什么，例如「用迁跃评估岗位 #12」「用迁跃为岗位 #12 定制简历」。在迁跃的功能页点 AI 功能时，弹窗里也会给出可以直接发给 Agent 的指令，一键复制。

**系统行为**：迁跃照常运行这个任务。到了要调用模型的地方，迁跃不请求任何模型服务，而是把这一步要问的内容（迁跃的要求、你的材料、JD，已按隐私设置脱敏）作为「迁跃请你代答」的请求返回给 Agent。Agent 写好后用 `answer_model_request` 交回，迁跃做程序校验：不合格时把原因作为下一个请求退回，合格就保存并给出下一步，直到返回最终结论。公司研究、沟通建议需要联网或检索时，Agent 指定要调用的工具，由迁跃执行，报告引用的来源都出自迁跃的搜索记录。

**输出**：和填了 Key 时一样的成果，存在迁跃里；任务列表里的步骤会标注「由你的 Agent 代答」。

- Agent 一般会自动一直交回到最终结论，中间不需要你操作。定制简历仍需你逐条确认修改；模拟面试仍需你本人回答。
- **建议在 Agent 里把迁跃的工具设为始终允许**，否则每交回一步都要你点一次确认。
- 同一段对话的后续请求只发新增内容，系统要求和之前一样时不重复；Agent 丢了上下文可以用 `get_model_request` 取全文。
- 由 Agent 代答时，评估不在分数线附近复评（同一个 Agent 再答一遍不是独立的样本），批量任务一次只做一个岗位。
- 结果质量取决于 Agent 所用的模型；程序校验（分数范围、引文必须出自原文、来源必须是搜过的）与填 Key 时相同。
- Agent 领走请求 30 分钟没有交回，任务会失败，可以在 Agent 里让它从断点继续（`resume_task`）。

**截图和助手也一样**：没有 Key 时，在迁跃里添加岗位或沟通记录带了截图，截图先存进迁跃（`data/uploads/`，7 天后自动删除），并发起一次「识别截图」任务；弹窗给出一句带运行编号的话，Agent 用 `get_task` 接手。截图作为图片附在请求里交给 Agent，同时写上本机路径，客户端不显示 MCP 图片时 Agent 可以按路径打开。识别结果按和填 Key 时相同的格式校验后存成岗位或沟通记录，弹窗里能看到 Agent 接手、做完，并直接打开结果。Agent 看不了图片时会取消任务，不会编造内容。

内置助手没有 Key 时，点「发送」会弹出同样的窗口：要复制的话就是你打的内容，带截图时截图先存进迁跃，话里附上截图编号，Agent 用 `view_screenshots` 看图。对话在你的 Agent 里进行，不保存到迁跃的助手历史。

## 检索

**操作**：在检索页输入一句话或若干关键词，可限定检索类别。

**检索范围**：材料、岗位（含 JD 正文）、沟通记录、成果和助手对话。

**输出**：带出处的片段，命中文字高亮；点击结果可打开原位置（岗位、成果、材料或对应对话）。

- 仅通过语义找到、字面未命中的结果标记「意思相近」。
- 未设置相关度阈值，结果会按数量补齐，排名靠后的结果可能仅具有弱语义关联。
- 重排在本机执行。首次检索需要建立索引，耗时随材料数量和设备性能变化。
- 检索历史保留在页面上，同一查询和类别组合仅保留一条，可删除。
- 也可将查询交给助手，由助手读取检索内容后回答。助手和 MCP 检索到的助手对话来自上次在检索页检索时的入库内容，不会实时更新。
- 此处的检索与定制简历、面试准备的证据检索相互独立：证据检索仅查询用户材料，不会将 JD 和 AI 生成的报告当作用户经历。

## 总览

**操作**：打开「总览」。

**系统行为**：根据全部岗位的阶段、阶段历史日期和最近一次评估计算统计数据。

**输出**：

| 模块 | 内容 |
| --- | --- |
| 数字卡片 | 岗位总数、已评估、值得投递（评估结论为值得或优先投递，且不存在已确认硬性阻断）、已投递、已面试、已获 Offer、未通过或放弃 |
| 应聘阶段漏斗 | 全部岗位 → 有完整 JD → 评估过 → 投递过 → 面试过 → 拿到 Offer。已结束岗位按历史到达的最远阶段计算，仍在流程中的岗位按当前阶段计算 |
| 评分分布 | 每个岗位对应一个点，横轴为分数，纵轴为添加日期，按结论分数线分段着色 |
| 节奏 | 新增、投递、面试三条曲线，支持按天、按周、按月查看；投递和面试按修改阶段时填写的日期计算 |
| 岗位来源对比 | 各来源的岗位数、占比、已评估数、平均评分、投递过、面试过、Offer 和投递率 |

每张图下方均附有指标含义和阅读方法。

## 成果

**操作**：打开「成果」页，按类型或岗位筛选。

**系统行为**：列出全部 AI 产出，包括评估报告、定制简历、公司研究、沟通建议、面试准备、模拟面试复盘和能力画像。

**输出**：集中查看全部产出。每份成果可单独导出 Markdown（右上角导出图标）；列表上方的「导出全部 N 份」下载一个 zip，选择类型后仅导出该类型。成果可删除，删除后的报告不会再被复用。

## 接口与终端命令

工作台上的操作均通过以下接口完成。完整接口文档位于 <http://127.0.0.1:8000/docs>。以下示例中的 `<运行编号>` 应替换为发起任务时返回的 `id`。

### 接口

```bash
# 检查服务状态。llm_configured 表示是否已配置模型 Key
curl http://127.0.0.1:8000/api/health

# 保存基础简历（Markdown）。补充资料使用 /api/documents/supplement，STAR 经历使用 /api/documents/star
curl -X PUT http://127.0.0.1:8000/api/documents/resume \
  -H 'Content-Type: application/json' \
  -d '{"content_md": "# 你的名字\n\n## 工作经历\n……"}'

# 添加岗位，返回的 id 为岗位编号
curl -X POST http://127.0.0.1:8000/api/jobs \
  -H 'Content-Type: application/json' \
  -d '{"company": "某公司", "title": "后端工程师", "jd_text": "岗位职责：……"}'

# 岗位列表。category：not_started、in_progress、closed；sort=score 按评分从高到低排序
curl 'http://127.0.0.1:8000/api/jobs?category=in_progress&sort=score'

# 修改应聘阶段。happened_on 不填写时为当天
curl -X POST http://127.0.0.1:8000/api/jobs/1/stage \
  -H 'Content-Type: application/json' \
  -d '{"stage": "applied", "happened_on": "2026-11-15"}'

# 保存一条沟通记录。speaker：recruiter 表示招聘方，me 表示我，transcript 表示整段粘贴
curl -X POST http://127.0.0.1:8000/api/jobs/1/communications \
  -H 'Content-Type: application/json' \
  -d '{"speaker": "recruiter", "text": "你好，简历看了。最快什么时候能到岗？"}'
```

**发起任务**统一使用 `POST /api/runs`，接口立即返回运行编号，任务在后台执行：

```bash
# kind 不填写时默认为评估。job_ids 在评估时可包含多个岗位、能力画像时包含 2–15 个岗位，其余任务一次一个
# conditions 为选填的本次要求；"force": true 表示输入未变也重新执行
curl -X POST http://127.0.0.1:8000/api/runs \
  -H 'Content-Type: application/json' \
  -d '{"job_ids": [1], "conditions": "只考虑上海，月薪不低于 30K"}'
```

| `kind` | 功能 |
| --- | --- |
| `evaluation`（默认） | 岗位评估 |
| `profile` | 能力画像 |
| `tailoring` | 定制简历（停留在等待确认状态） |
| `company_research` | 公司研究 |
| `communication` | 沟通建议 |
| `interview_prep` | 面试准备 |
| `mock_interview` | 模拟面试（问答通过 WebSocket 进行，见下文） |
| `collection` | 采集（参数见下文） |

```bash
printf '粘贴发起任务时返回的运行编号：'
read -r RUN_ID
curl -N "http://127.0.0.1:8000/api/runs/${RUN_ID}/events"     # 查看进度
curl "http://127.0.0.1:8000/api/runs/${RUN_ID}"               # 查看运行状态
curl -X POST "http://127.0.0.1:8000/api/runs/${RUN_ID}/cancel" # 取消任务
curl -X POST "http://127.0.0.1:8000/api/runs/${RUN_ID}/resume" # 从断点继续

# 成果：列表（按 kind、job_id 筛选）、导出单份、导出全部（zip）、删除
curl 'http://127.0.0.1:8000/api/artifacts?kind=evaluation&job_id=1'
curl http://127.0.0.1:8000/api/artifacts/1/export
curl -o artifacts.zip http://127.0.0.1:8000/api/artifacts/export
curl -X DELETE http://127.0.0.1:8000/api/artifacts/1
```

**定制简历确认**：运行停留在 `waiting_user` 时，`GET /api/runs/<运行编号>` 返回的 `pending.edits` 为逐条修改，`pending.preview_md` 为接受全部修改后的内容，`pending.gaps` 为材料中缺少证据的岗位要求，`pending.questions` 为模型需要用户回答的问题。每条修改的 `fact_check` 为 `needs_confirmation` 时，需要用户确认属实；`unverified` 列出材料中找不到的数字和技术词。

```bash
# 预览仅接受部分修改时的简历，不保存
curl -X POST "http://127.0.0.1:8000/api/runs/${RUN_ID}/preview" \
  -H 'Content-Type: application/json' -d '{"accepted": [1, 2]}'

# 提交接受的修改编号并生成定制简历。overrides 为用户手动修改的新内容，按原样应用
curl -X POST "http://127.0.0.1:8000/api/runs/${RUN_ID}/respond" \
  -H 'Content-Type: application/json' \
  -d '{"accepted": [1, 2, 4], "overrides": {"2": "- 负责客服助手项目，转接率降到 28%。"}}'
```

**采集**：

```bash
# per_search 为每个搜索新增的岗位数，默认 10，最多 20；单次总数不超过 100 个
curl -X POST http://127.0.0.1:8000/api/runs \
  -H 'Content-Type: application/json' \
  -d '{"kind": "collection", "collection": {"platforms": ["zhaopin", "liepin"], "queries": ["前端开发"], "cities": ["北京"], "per_search": 5}}'
# collection 的可选项："min_salary": 20, "years": 4, "exclude": ["实习"], "evaluate": true,
# "relevant_only": false（不执行相关性筛选），"list_only": true（不读取详情页，仅保存列表信息）
# 各平台分别设置数量："per_platform": {"boss": 15, "51job": 20}

# 打开专用浏览器供用户登录
curl -X POST http://127.0.0.1:8000/api/collection/browser \
  -H 'Content-Type: application/json' -d '{"platform": "51job"}'
```

**助手**：

```bash
# 发送一条消息。第一条 conversation 事件中的 id 为对话编号
curl -N -X POST http://127.0.0.1:8000/api/chat/stream \
  -H 'Content-Type: application/json' \
  -d '{"message": "我现在有哪些岗位？"}'

# 携带对话编号继续对话
curl -N -X POST http://127.0.0.1:8000/api/chat/stream \
  -H 'Content-Type: application/json' \
  -d '{"conversation_id": "<对话编号>", "message": "这个岗位我投了"}'

# 暂停等待确认时（confirm 事件，每个操作带一个 id），approved 列出要执行的操作，空列表表示均不执行
curl -N -X POST http://127.0.0.1:8000/api/chat/<对话编号>/confirm \
  -H 'Content-Type: application/json' -d '{"approved": ["<操作 id>"]}'

curl http://127.0.0.1:8000/api/chat/<对话编号>   # 获取该对话的历史记录
```

事件流包含：`conversation` 对话编号、`token` 助手当前输出、`tool` 工具调用、`run` 交给专员发起的运行、`progress` 专员进度、`result` 专员完成后成果开头的原文、`confirm` 等待用户确认、`done` 本轮结束。

**检索**：

```bash
# 全局检索，type 可指定多个：material、job、communication、artifact、chat
curl -G http://127.0.0.1:8000/api/search --data-urlencode 'q=要 Kafka 的岗位' -d type=job

# 仅检索材料（定制简历、面试准备的证据检索采用此方式）
curl -G http://127.0.0.1:8000/api/knowledge/search --data-urlencode 'q=有 RAG 项目落地经验'
```

**统计**：`GET /api/overview` 返回总览页的全部数据，`GET /api/jobs/overview` 返回按阶段和类别统计的岗位数。

**模拟面试**由一次 `mock_interview` 运行和一条 WebSocket 连接（支持双向实时收发）组成，地址为 `/api/runs/<运行编号>/interview`，消息格式见 `backend/app/api/interviews.py`。

### 终端命令

在 `backend/` 目录下运行，且后端须先启动。后端未使用 8000 端口时，添加 `--server 127.0.0.1:端口`。

**采集**：

```bash
# 关键词 城市 平台:数量 ……   数量为每个搜索新增的岗位数（1–20），不填写时为 10
uv run python scripts/collect.py 前端开发 北京 boss:15 51job:20

# 关键词和城市可指定多个，使用逗号分隔
uv run python scripts/collect.py 前端开发,React 北京,上海 zhaopin

# 筛选：跳过月薪上限不到 20K、要求年限比 4 年多一年以上、职位名包含「实习」或「外包」的岗位
uv run python scripts/collect.py 前端开发 北京 boss:10 --min-salary 20 --years 4 --exclude 实习,外包

uv run python scripts/collect.py 前端开发 北京 zhaopin:5 --evaluate    # 采集完成后自动评估新增岗位
uv run python scripts/collect.py 前端开发 北京 boss:5 --list-only      # 不读取详情页，仅保存列表信息
uv run python scripts/collect.py --login liepin                         # 仅打开平台供用户登录
```

平台标识为 `51job`（前程无忧）、`liepin`（猎聘）、`zhaopin`（智联招聘）、`boss`（BOSS 直聘）。终端显示读取页码和保存数量，最后列出每个搜索新增的岗位编号。按 Ctrl+C 停止。

**模拟面试**：

```bash
# 为 1 号岗位创建一场模拟面试。第二个参数选填，用于指定面试官角色和练习重点
uv run python scripts/mock_interview.py 1 "技术面，重点练项目深挖"
```

每轮输入一行回答并按回车；直接回车表示结束，系统复盘已回答部分。按 Ctrl+C 退出不会丢失进度，再次运行相同命令即可继续。

## 数据存储与隐私

「设置 → 模型」里的「发送给模型前隐藏个人信息」默认开启，可用占位符替换中国大陆手机号、邮箱和自定义词。自定义词按整行及行内由空白分隔的词分别匹配。规则覆盖发给模型的简历、JD、聊天和工具结果。本地原文仍可查看。不需要时取消勾选并保存，之后按原文发送。联网搜索和外部 MCP 客户端各有自己的数据访问范围。

工作区的向量检索在本机运行。公司研究和面经搜索会把查询词发给选定的搜索服务。**截图没法脱敏**：添加岗位、添加沟通和助手里的截图会以原图发给 AI（填了 Key 时发给模型服务，没填时交给你的 Agent），不再逐次询问。发送前请自己遮挡姓名、手机号、邮箱等个人信息。

业务数据库、检索模型和日志等默认保存在仓库根目录的 `data/`。环境配置可另存于 `backend/.env`。

| 路径 | 内容 |
| --- | --- |
| `data/qianyue.db` | 岗位、材料、成果、沟通记录、设置页保存的 Key 等业务数据 |
| `data/checkpoints.db` | 运行断点（断点续跑、等待确认的修改方案、模拟面试问答）和助手对话历史，由 LangGraph 管理 |
| `data/vectors/` | 向量库（Qdrant 本地模式），根据用户材料和全部内容自动生成，删除后自动重建 |
| `data/models/` | Embedding 和 Rerank 模型文件，约 1.1 GB，可重新下载 |
| `data/browser/` | 专用浏览器用户目录，包含各平台登录状态；删除后需要重新登录 |
| `data/logs/app.log` | 运行日志。每行前两个方括号分别为请求编号和运行编号；响应头 `X-Request-ID` 为请求编号，使用运行编号执行 `grep` 可查看一次评估的完整过程 |

- 设置页保存的 Key 以明文存储在 `data/qianyue.db`，与 `.env` 一样仅保存在本机。设置接口仅返回是否已配置和末尾 4 位；按住眼睛图标时，才获取一次完整 Key。
- 添加岗位或沟通记录时，截图仅提交给模型识别一次，不保存；助手对话中的截图作为消息的一部分，保存在 `data/checkpoints.db` 的对话历史中。没有模型 Key、交给 Agent 识别的截图存在 `data/uploads/`，7 天后启动时自动删除。
- **备份或迁移设备**：复制整个 `data/` 和 `backend/.env`。`data/models/`、`data/vectors/`、`data/browser/` 可不复制。
- 要把业务数据放在其他位置，见[启动参数](#启动参数)。

## 常见问题与排查

| 现象 | 原因与处理方法 |
| --- | --- |
| 开始任务后提示「还没有配置模型 Key」 | 在设置页填写模型地址、模型名和 Key，保存后立即生效，无需重启 |
| 添加截图时报错 | 模型不支持图片输入。改用支持图片输入的模型，或直接粘贴 JD 文字 |
| 评估提示缺少简历或 JD 不完整 | 先在材料页保存基础简历；对「JD 不完整」的岗位，在岗位信息页补充 JD |
| 公司研究或面经无法搜索到内容 | 默认的 DuckDuckGo 偶尔无法获得结果。稍后重试，或在设置页更换搜索服务并填写相应 Key |
| 采集页提示没有找到 Chrome | 安装 Chrome。若已经安装在非默认位置，在 `backend/.env` 设置 `QIANYUE_CHROME_PATH` 并重启。 |
| 采集停止并提示需要登录或验证 | 在自动打开的专用浏览器中完成登录或验证，然后在采集记录中点击「从断点继续」 |
| 首次定制或检索速度较慢 | 查看 `data/logs/app.log` 是否已记录「检索模型已就绪」。模型下载和初次建立索引均需要时间，见[本地检索模型](#本地检索模型) |
| 任务显示「没有完成」 | 服务中途停止、任务被取消或发生错误。任务面板中记录原因；点击「从断点继续」，已完成的步骤不会重复执行 |
| 需要查看一次任务的完整过程 | 在 `data/logs/app.log` 中使用 `grep` 检索运行编号 |
| 8000 端口被占用 | 按[启动参数](#启动参数)更换端口，然后打开终端显示的新地址 |
